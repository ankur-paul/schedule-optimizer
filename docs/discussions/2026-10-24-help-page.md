# Help page (discussion, 24 Oct 2026)

Roadmap idea #4. Two rounds of questions. The plan below is what came out of them, and the grilling notes at the end
record the reasons and the options turned down.

## Plan

### What changes for the user

- **Help pages at `/help`.** These are plain pages next to the app, like `/privacy` and `/terms`. They are public,
  readable without JavaScript and usable on a phone. In-app links open them in a new tab. The working copy is in
  `localStorage`, so nothing is lost.
- **Pages:**
  - `/help` is the index. It has one line per page and the list of sections under it.
  - `/help/start`, *Your first timetable*, is a tutorial of about 5 minutes on the sample college: load the sample,
    look at the data checks, generate, read the score, lock a class, regenerate, then print.
  - `/help/data`: the Excel template and import, import errors, departments and rooms (who may use which room),
    lab batches and batch teachers, lunch candidates, and the data checks.
  - `/help/generate`: the exact solver and the quick draft, the time limit, *Can't be built* with each cause and
    its fix, *Couldn't finish*, and partial timetables.
  - `/help/timetable`: the score and the soft rules S1–S4, locks and *Regenerate*, drag and drop, print and CSV.
  - `/help/online`: signing in, institutes and roles, saving online, versions and conflicts, publishing and the
    public link.
  - `/help/troubleshooting`: solver offline, the email link didn't arrive, "Only the admin can do that", import
    rejected, *Couldn't finish* on short limits.
- **Each section has a stable anchor**, e.g. `/help/data#lab-batches`, so the app links to the exact spot.
- **Text plus screenshots.** Short steps with a few screenshots of the sample college, made by a script so they can
  be regenerated when the UI changes.
- **English only.** The pages are written with the `/no-ai-slop` skill.

### Where the app links to help

The user left this to Claude. Links go where people get stuck:

- **Problem cards (highest value):** each cause on *Can't be built*, the *Couldn't finish* card, the unplaced-cause
  groups on a partial timetable, import errors and the step ② data checks link to the section that explains them.
- **ⓘ tooltips:** *Learn more* only where the help section says more than the tooltip. A tooltip that already says
  everything gets no link.
- **Step hints:** each step's one-line hint ends with a *Help* link to that step's page.
- **Always there:** *Help* in the footer next to *Privacy* and *Terms* (works signed out) and in the account menu.
- **Troubleshooting** is linked from the index and from the solver-offline banner.
- The public timetable page gets no help link; students and teachers only read it.

### How it's built

- **Same pipeline as the legal pages (T23).** Markdown in `web/src/help/*.md`, turned into static HTML at build
  time with `marked`. Headings get ids from their text, and a heading can set its own id where the text would make
  a poor anchor. Pages share one layout: the Lattice header, *Back to Lattice*, a contents list, and print styles.
- **Help links in the app** go through one helper, e.g. `helpHref('data', 'lab-batches')`, with the page and anchor
  typed from a list generated from the Markdown headings. A Vitest test fails if any link points at a missing page
  or anchor.
- **`help` can't be a handle.** Today `/help/data` matches the public-link rewrite (`isPublishedRewrite` in
  `web/src/published/path.ts`) and would open `published.html`. The pass adds `help` to `NOT_HANDLES`, to the
  reserved handles in the database (a migration, refusing it if an institute already holds it), and to the host
  rewrite rules in the deploy list.
- **Screenshots:** a script (`npm run help:shots`, Playwright as a dev dependency) starts the preview server, loads
  the sample college and a fixed timetable (a new fixture, `shared/fixtures/sample-timetable.json`, saved once from
  a solver run, so images don't change between runs), and saves
  light-theme PNGs to `web/public/help/`. It needs no solver and no Supabase. Online screenshots use a mocked
  signed-in state, or are left out where mocking costs too much.
- **The agent (#5)** reads the same Markdown files. One topic per section with a plain heading is enough for it.
- **No policy change.** The pages collect nothing and load no analytics.

### Keeping it current

- A new CLAUDE.md rule, next to the FEATURES.md one: a commit that changes what users see updates the matching help
  section in the same commit, and reruns `npm run help:shots` if a screenshot changed.
- The link test catches renamed or deleted sections.

### Tickets

- **T32 Help pages: build and layout** (Prereqs: —). The Markdown-to-HTML build for `/help/*`, the layout, anchors,
  the generated anchor list, `helpHref`, the link test, `help` reserved in `NOT_HANDLES` and the database, the
  footer and account-menu links, and the CLAUDE.md rule. The pages hold their headings only.
- **T33 Help screenshots script** (Prereqs: —). `npm run help:shots` with Playwright, the fixed timetable fixture,
  and output that doesn't change between runs. Runs alongside T32.
- **T34 Help content: start, data, generate, timetable, troubleshooting** (Prereqs: T32, T33). The text and
  screenshots, written with `/no-ai-slop`, plus the in-app links for these areas (problem cards, tooltips, step
  hints).
- **T35 Help content: online and institutes** (Prereqs: T32, T33, T31). The online page and its links. It waits
  for T29 (versions, publish) and T31 (policy v2, consent on save) so it describes the finished flow.

T34 and T35 run in parallel once T32 and T33 are in.

### Env vars and services (copy to the roadmap's deploy list)

- No new env vars.
- The host serves `/help` and `/help/<page>` without `.html` (Cloudflare Pages does by default; Vercel needs
  `"cleanUrls": true`), and its public-link rewrite must skip `/help/*`.

### Not in this pass

- Videos or GIFs.
- Other languages.
- Search inside help; the browser's find is enough for six pages.
- A help drawer inside the app.
- Help on the public timetable page.
- The first-login walkthrough (#7). It can follow the `/help/start` path later.

## Grilling notes

- **Q1 Cover all four areas** (data entry, generating, reading the timetable, online and institutes), not only the
  hardest parts.
- **Q2 Text plus screenshots.** Rejected: text only (hard to follow where a step depends on the screen layout); GIFs
  (large, and every UI change means recording them again).
- **Q3 Static `/help` pages opened in a new tab.** They reuse T23's build, are public and linkable, and the agent can
  read them. Rejected: a side panel in the app (more UI, and a public page is still needed); both.
- **Q4 English only,** written with `/no-ai-slop`. Rejected: adding Hindi or Punjabi (every page kept up to date
  twice).
- **Q5 Index plus one page per area,** with anchored sections. Rejected: one long page (slow to scan on a phone);
  a page per topic (about 15 small pages, and it's easy to lose your place).
- **Q6 A tutorial on the sample college** as well as the reference pages. Rejected: a tutorial from your own Excel
  (longer, and it can stall on import errors); reference only.
- **Q7 Link placement left to Claude:** problem cards, ⓘ tooltips where the help adds something, step hints,
  footer and account menu, plus a troubleshooting page.
- **Q8 A CLAUDE.md rule plus a link test** keep the help current, and screenshots come from one script. Rejected:
  the rule alone; a review before each deploy.
- **Found while planning:** `/help/<page>` is a two-segment path, so the public-link rewrite would catch it. `help`
  becomes a reserved handle.
