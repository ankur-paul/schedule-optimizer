## Known issues / cuts

- [T03] Heuristic runs until its time limit unless it hits score 0 (the sample levels off at 18, all batch-idle), so `timeMs` ≈ the limit. Results depend on timing, so they aren't exactly reproducible for a given seed.
- [T04] CP-SAT needs ~2 s before its first solution on the sample; `timeLimitSec` < 3 may return `error` (client then falls back to heuristic). Empty `lunchCandidates` disables H8.
- [T05] Any settings edit clears `result` and `locks` (placements point at day/period indexes).
- [T07] Exact – CP-SAT with the server off shows an error and keeps the previous result (no fallback, by design; Auto falls back). The infeasible → partial-heuristic path is unit-tested but not clicked through (needs T06 edit tables).
- [T06] Importing or loading the sample replaces all data tables (after a confirm). Inline table edits do not clear an existing timetable; T07's validator re-checks it. A course with an error is left out of the load numbers until fixed.
- [T10] Locks are kept when the result is replaced, so an engine run that can't honour them (e.g. a lock that blocks every other slot) shows up as unplaced sessions rather than a dropped lock. Print sheets don't show 🔒.
- [T13] Dragging works in the Section view only, with a mouse or pen (touch not tried; no keyboard dragging, so use *Lock here* in the dialog instead). Undo puts back the timetable from just before that move, so undoing an older move also reverts any made after it.
- [T05] A browser that already saved the app state keeps its old (sample) week setup until *Start over*.
- [T04] CP-SAT bugs found by the new tests (strict xfail, details in `docs/cpsat-test-report.md`): a `feasible` (non-optimal) result reports an inflated score (the UI re-scores, so only `/solve` callers see it); a break-period lunch candidate makes H8 stricter than the validator; duplicate course ids give a misleading "infeasible".
- [chore] The ticket board sees local branches and worktrees only (not other machines' unpushed work); an uncommitted ticket edit is dated by its file time, so a stale `git checkout` can briefly outrank a newer commit elsewhere.
- [T17] Infeasibility causes aren't shown anywhere until T18 builds step ③'s *can't be built* card. Room load checks are lower bounds: a pool can be under capacity and still impossible (e.g. two sections need the same lab at the only times both are free).
- [T12] Cancelling a CP-SAT run only stops the browser waiting: the server keeps solving until its time limit, and its answer is ignored.
- [T18] Step ③'s failure card stays until the next run, even after the data is fixed. The server reports "no solution in time" as `status: "error"`, so the client spots a timeout by its message ("found no solution in"). Dragging an unplaced class in from a partial timetable was not clicked through for T18 (the over-booked test data had no free slot); the drag code is T13's, unchanged.
- [T12] No user test was run: nobody new has tried the app without instructions, so first-use confusion is untested.
